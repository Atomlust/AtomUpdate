# 01 需求分析

## 1. 产品定位

AtomUpdate 是一套**面向 .NET 10 应用**的在线更新平台，由三个角色组成：

| 角色 | 对应物 | 一句话职责 |
|---|---|---|
| 服务端 | AtomUpdate.Api + AtomUpdate.Web | 存元数据、分发更新包、下发更新策略、管理版本发布 |
| 客户端 | AtomUpdate（SDK）+ AtomUpdate.Updater | 检查、下载、校验、安装、回滚 |
| 生产端 | AtomUpdate.Packager（GUI + Cli / dotnet tool） | 打包、经服务端 API 上传、推送版本元数据 |

**关键架构决策：**

1. **更新文件由服务端统一存储与分发**——文件由 Packager 登录 JWT 后经服务端上传 API（`POST /api/manage/projects/{projectId}/apps/{appId}/upload`）写入 `Storage:Root`，服务端同步计算 SHA-256 并经 `/uploads` 静态分发；API 元数据只存 URL、哈希等（签名字段可空）。私有化部署可将 StorageRoot 指向共享卷/对象存储挂载。
2. **响应分层**：无更新时返回精简响应（3 个字段），有更新时返回完整响应；策略用 `policyVersion` 做增量下发；HTTP 层用 ETag/304 做第二层优化。
3. **下载模式由触发场景决定**：启动/手动/强制 → 前台不可取消；轮询/网络恢复/休眠恢复 → 静默可取消。
4. **更新器是独立进程**，主程序只负责下载与调度；提权收敛在更新器内，主程序永不提权。
5. **租户 → 项目 → 应用 → 通道** 隔离模型；通道为全局枚举预设（dev/preview/beta/rc/stable，不可自定义）。

## 2. 核心功能列表

### 服务端（Api + 管理后台）

- 更新检查 API（响应分层 + policyVersion + ETag/304），公开端点
- 安装/下载/统计上报 API（`/api/stats/*`、`/api/report/*`），公开端点，失败可落盘补报
- 版本发布 API（创建草稿、发布/撤回/回滚、multipart 包文件上传）
- 管理后台（Blazor Auto + NeoUI.Blazor）：项目/应用/版本/用户/审计日志/统计概览
- 邮箱/密码登录 JWT 鉴权；多租户隔离（全局查询过滤器强制）
- PostgreSQL 默认数据库（可换 SQLite 轻量部署）；IdGen 雪花 ID 主键

### 打包工具（Packager）

- Avalonia 四步发布向导（登录与目标 → 打包 → 日志 → 发布，中英双语、亮暗主题）
- 完整包 zip / exe（Inno Setup 集成）；文件级增量包（MVP）
- 结构化更新日志（新增/优化/修复/注意，Markdown，多语言）
- 经服务端上传端点上传包文件（服务端落盘并计算 SHA-256），推送版本元数据
- CLI 四子命令 publish/pack/upload/list（dotnet tool `atomupdate-packager`，可被 CI 调用）

### 客户端 SDK 与更新器

- SDK（NuGet `AtomUpdate`，net10.0）：五级配置优先级、四层策略合并、六场景触发下载、轮询（抖动+退避）、策略缓存、离线补报队列
- `IAtomUpdater` 门面 + 12 类事件 + 10 项分层子服务（均可替换）
- 标准更新器（Native AOT 单文件，6 RID 内嵌）：互斥、SHA256 校验、备份/回滚、merge/replace 替换策略、钩子、按需提权、双进程自升级、安装结果直传与 SDK 补报
- 基础安装统计（机器指纹匿名哈希 + installationId 去重）

## 3. 术语表

| 术语 | 含义 |
|---|---|
| 租户（Tenant） | 平台隔离顶层单元，拥有独立用户与项目空间 |
| 项目（Project） | 租户内的产品单元，以 `projectKey`（全局唯一短名）标识 |
| 应用（App） | 一个可更新的客户端程序，`appId` 形如 `com.company.myapp`；**平台（windows/macos/linux）是应用属性，创建后不可改**——跨平台分发 = 同项目下多个应用 |
| 通道（Channel） | 发布轨道，全局枚举预设：dev 开发版 / preview 预览版 / beta 公测版 / rc 候选版 / stable 正式稳定版 |
| 版本（Release） | 应用内一次发布，**一条版本号在应用内只有一条记录**（唯一键 `(AppId, Version)`） |
| 包资产（ReleaseAsset） | 版本下的一个包文件；**架构（x64/arm64/x86）是资产属性**——同一版本的多个架构包是同一条 Release 下的多个资产 |
| 完整包 / 增量包 | full：全量文件包；delta：相对基线版本的文件级差异包（files + delete 清单 + manifest） |
| 更新策略（UpdatePolicy） | 应用级策略：轮询、下载触发、安装模式、防降级、推迟、限速等；`policyVersion` 随修改递增用于增量下发 |
| ETag | 更新检查响应的强校验器，`hash16(projectKey|appId|platform|arch|currentVersion|latestVersion|p{policyVersion})`；请求带 `If-None-Match` 命中即返回 304 |
| 强制更新 | 服务端 `forceUpdate` 标记或当前版本低于 `minSupportedVersion`：前台下载、不可取消/推迟、阻止进入主界面 |
| 更新器（Updater） | 独立进程，主程序退出后执行备份/替换/回滚/重启；Native AOT 单文件，由 SDK 内嵌分发 |
| 机器指纹 | `SHA256(MachineGuid|machineName|cpuModel|租户盐)` 匿名哈希，无 PII，可关闭 |
| installationId | 客户端首次生成的匿名 UUID，标识一次安装（按应用隔离） |
| 补报 | 上报失败落盘（`pending-reports/`、`reported=false` 状态文件），SDK 下次启动重传 |
