## 2. 技术风险

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| Windows 文件占用导致替换失败（杀软、自启动、句柄泄漏） | 高 | 高 | rename-replace + 重试 + 回滚；钩子预留 preInstall 停服务；联调阶段覆盖常见杀软场景 |
| ETag/304 与 policyVersion 双层缓存的一致性（客户端缓存陈旧策略） | 中 | 中 | policyUnchanged 判定以服务端为准；SDK 缓存带过期时间兜底；Q1 修正避免漏发 |
| macOS 平台（codesign/notarization、Gatekeeper 对 Updater 子进程的拦截） | 中 | 中 | MVP 以 zip 绿色包为主；文档化公证流程；Updater 二进制随宿主一起签名 |
| Linux 桌面碎片化（通知 libnotify、提权 pkexec 可用性） | 中 | 低 | MVP Linux 以控制台/服务器场景优先，桌面能力降级为应用内通知 |
| 第三方存储差异（Range 支持、URL 时效、上传分片） | 中 | 低 | **2026-10-08 起发布链路不再直连第三方存储**（§4.12）：上传走服务端 API、下载走 `/uploads` 静态分发（支持 Range）；仅当部署外挂第三方存储/CDN 承载下载时需确认 Range 支持，不支持时 SDK 整包重下（Q21） |
| Inno Setup 外部依赖（打包机需安装 ISCC） | 低 | 低 | 探测+引导；zip 为缺省包类型 |
| EF Core + PostgreSQL 分区/批量写入的统计高基数 | 中 | 中 | 异步批量写 + 按月分区；MVP 数据量有限，先简单后演进 |
| IdGen ID 重复（多实例 GeneratorId 配置冲突）或时钟回拨致生成异常 | 低 | 高 | 每实例唯一 GeneratorId（配置注入 + 启动日志自检）；部署要求 NTP 同步、避免大幅时钟回拨；IdGen 对时钟回拨抛 `InvalidSystemClockException`（已核源码），调用侧需捕获并告警而非静默重试；联调覆盖多实例场景 |
| Blazor Auto 双渲染模式的 WASM 加载与 UI 组件库兼容坑（AntDesign 时代提出，2026-10-07 换库后为 NeoUI.Blazor） | 中 | 低 | M2 第一周做技术验证 spike；必要时可回退 InteractiveServer（全局模式一处声明切换，2026-10-06）。换库后的新增面：库以**预编译 Tailwind** 交付，样式集中在 `components.css` 的 `@layer` 内——好处是我们的无层覆盖天然优先，坏处是可用钩子只有 `[data-slot]`/`[role=…]`/工具类名，库升级改名即失效；缓解：组件库版本锁在 CPM，且 `app.css` 每条覆盖都注释了实测钩子 |
| 临时配置中的 API Key 落盘 %Temp% | 中 | 中 | **清理已在 M4 落地**：更新器在 `RunAsync` 的 `finally` 删除本组件写入的启动配置与自升级交接文件（只按名称约定删自己写的，用户手写 `--config` 保留；提权回环时子进程先删、父进程容错跳过），正常失败/异常同样清理。未显式设 ACL，依赖 `%Temp%` 目录默认的"仅当前用户 + SYSTEM/管理员"权限；**残余风险**：更新器被强杀（或断电）时文件可能残留，需要更强保证的部署应改用受控目录 + 由宿主清理。应用 Key 仅授予 report scope；长期方案评估短时 token |
| 签名校验默认关闭（2026-10-06 决策） | 中 | 中 | 部署方需知晓：默认形态下服务端被攻破可直接投毒（SHA256+可信元数据仍兜底传输/存储篡改场景）；文档与部署手册明示风险，需防护的部署显式开启验签——签名由发布方在 Packager 之外写入元数据（**Packager 侧签名已移除，2026-10-08**，见 §4.12） |
| 事件在后台线程触发，宿主误用导致 UI 跨线程异常 | 中 | 低 | 文档明确约定 + UI 适配包内置 Dispatcher 调度；示例代码示范 |
| 六 RID 产物 CI 耗时与缓存 | 低 | 低 | RID 矩阵并行 job + 二进制缓存 |
| Native AOT 兼容性（Q12 选择 AOT 引入） | 中 | 中 | JSON 序列化一律 source-gen；禁反射动态加载与 Refit 反射实现；CI 增加 AOT 发布验证；osx RID 需 macOS 构建机（GitHub Actions osx runner 或自建 host）；自定义 Pipeline 已放弃（2026-10-06），AOT 互斥风险消除 |

### 4.12 发布链路简化：移除 Packager 侧签名与凭据（2026-10-08，用户指令）

| 决策 | 结论 | 依据 / 代价 |
|---|---|---|
| **移除 Packager 侧签名、凭据与直传存储** | 删除 `Signing/`（RsaSigner/RsaKeyMaterial/ISigner）、`Credentials/`（EncryptedCredentialStore 及 DPAPI/AES 加密存储）、`Storage/` 直传上传器（LocalStorageUploader/S3StorageUploader，随之移除 AWSSDK.S3 依赖）与 GUI 凭据管理对话框 | 私有部署的发布者多数没有证书与对象存储凭据可配，"登录即可发布"把使用门槛降到零；签名模型本身未废（见下行保留项），只是不再由 Packager 强绑定 |
