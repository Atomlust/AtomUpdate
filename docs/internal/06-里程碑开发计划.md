# 06 里程碑开发计划

## 1. 计划假设

- 团队：**2~3 名 .NET 开发**（1 名偏服务端/后台，1~2 名偏客户端/桌面）。
- 里程碑按周估算为理想工时；并行度体现在模块级拆分。
- 每个 M 结束有可演示物（Demo）；MVP = M0~M6，总计约 **14~17 周**（Q22：文件级增量纳入 MVP，排期弹性 +1 周）。
- CI/CD（GitHub Actions 或同类）在 M0 建立：构建、单测、RID 发布、NuGet 打包。

## 2. 里程碑总览

```
M0 工程骨架        ████░░░░░░░░░░░░░░  1 周
M1 API 核心        ░░████████░░░░░░░░  3 周   ──┐ 服务端线
M2 管理后台        ░░░░░░░░░████████░  4 周   ──┘（可与 M3/M4 并行）
M3 客户端 SDK      ░░░░████████░░░░░░  4 周   ──┐ 客户端线
M4 标准更新器      ░░░░░░░░░████████░  4 周   ──┘

M6 统计+联调+验收  ░░░░░░░░░░░░░░████  2 周
```

依赖关系：

```
M0 ─► M1 ─► M2, M5
M0 ─► M3 ─► M4
M1(mock)+M3+M4+M5 ─► M6
```

> 关键路径：M0 → M3 → M4 → M6。服务端先行提供契约（OpenAPI + Core DTO）后，客户端线即可用 mock 开工，不被 M1 阻塞。
