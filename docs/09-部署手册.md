# 09 部署手册

> 私有化部署（MVP）：单镜像一体化（Web 单进程托管 Api，docs/02 §2）；默认 SQLite 轻量单容器，可选 PostgreSQL 生产形态。
> 镜像交付两条路径：默认现场 `docker compose build`（不依赖 registry）；另有 `tools/release-web.ps1`（手动）与 Pipewright 流水线（main/release 分支自动）构建并推送私有 registry `docker.atomlust.com/atomupdate/web`。
> 数据库选型对比见 [11 数据库选型与部署指南](11-数据库选型与部署指南.md)（SQLite 已实现，`Database:Provider=sqlite` 为代码零配置默认）；compose 默认形态为 SQLite 轻量单容器，生产多实例/高并发用 PostgreSQL（`--profile postgres`，§1.1）。

## 1. 快速启动

```powershell
# 仓库根目录；SQLite 形态零必填配置，直接启动
docker compose up -d --build

curl http://localhost:8081/health   # {"status":"ok"}
```

首次访问 `http://localhost:8081` 进入**设置向导**：创建平台管理员（用户名可选、邮箱、密码）后直接登录后台。

- JWT 签名密钥未配置时自动生成并持久化到数据卷（`/data/jwt-signing-key.txt`，库文件同目录），容器重建不丢失、已签发 token 不失效
- 若预配了 `Auth:Bootstrap:Password`（CI/自动化场景），跳过向导直接用预配管理员登录
- 已初始化的系统访问向导页自动跳回登录页；`POST /api/manage/auth/setup` 仅用户表为空时可用（表非空 409）

登录：`http://localhost:8081` 管理后台，或 `POST /api/manage/auth/login {email,password}` 获取 JWT（`email` 字段接受用户名或邮箱）。

### 1.1 生产形态（PostgreSQL 双容器，多实例/高并发）

```powershell
$env:JWT_SIGNING_KEY = '<至少32字符随机串>'
$env:BOOTSTRAP_PASSWORD = '<管理员初始密码>'
docker compose --profile postgres up -d --build web-pg
```

两形态共用宿主端口 8081（容器内均为 8080），**切换前先 `docker compose down`**。`web-pg` 启动 `web-pg` + `postgres` 双容器（postgres 不暴露宿主机端口）；库落 `pgdata` 卷。多实例部署须给每个实例互异的 `IdGen__GeneratorId`，且**必须显式配置同一 `JWT_SIGNING_KEY`**（实例间共享验签；密钥文件自动生成仅适用单实例形态）。

### 1.2 脚本部署（接入既有 Docker 网络）

已有反向代理所在 Docker 网络（如 `webnet`）时，用部署脚本一键接入，同网络反代以容器名直连：

```powershell
pwsh tools/deploy-web.ps1                                   # 默认：webnet 网络、宿主 8081 仅回环、命名卷
pwsh tools/deploy-web.ps1 -Image docker.atomlust.com/atomupdate/web:1.0.0
pwsh tools/deploy-web.ps1 -Port 8090 -Public                # 端口直接对外
pwsh tools/deploy-web.ps1 -AppEnv @('Auth__Bootstrap__Password=xxx')  # 预配管理员跳过向导（裸 docker run 须用双下划线配置键，非 compose 的 BOOTSTRAP_PASSWORD 别名）
```

脚本行为：网络不存在自动创建 → 幂等重建容器（已存在先移除）→ 端口默认绑 `127.0.0.1:8081`（同机反代转发；`-Public` 绑 `0.0.0.0`）→ 挂数据卷 `atomupdate-data:/data`（库 + JWT 密钥）与 `atomupdate-uploads:/data/uploads`。反代 upstream：`http://atomupdate-web:8080`（webnet 内）或 `http://127.0.0.1:8081`（同机）。bind mount 变体：`-DataVolume <宿主目录>`（注意 `chown -R 1654:1654` 给 APP_UID 写权限）。

## 2. 配置项（compose `environment` / 环境变量）

| 变量 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `JWT_SIGNING_KEY` | 默认形态可选 | 自动生成 | JWT 签名密钥（映射 `Auth:Jwt:SigningKey`）；未配置时自动生成并持久化到密钥文件（SQLite 库文件同目录，`Auth:Jwt:AutoKeyFile` 可覆盖路径）；无法落盘或 PostgreSQL 多实例须显式配置 |
| `BOOTSTRAP_PASSWORD` | 默认形态可选 | — | 预配管理员初始密码（仅用户表为空时种子生效）；未配置时首次访问进设置向导 |
| `BOOTSTRAP_EMAIL` | | `admin@example.com` | 预配管理员邮箱 |
| `BOOTSTRAP_USERNAME` | | `admin` | 预配管理员用户名（可选登录名，全局唯一；设置后可用"用户名+密码"登录） |
| `BOOTSTRAP_TENANT` | | `default` | 引导租户 slug |
| `Database__MigrateOnStartup` | | 代码默认：sqlite `true` / npgsql `false`；compose `web-pg` 显式设为 `true` | 启动时执行 EF 迁移（幂等）；PostgreSQL 多实例部署须自行改 `false`、仅让一个实例首个启动或手动迁移一次 |
| `ConnectionStrings__Postgres` | | compose 内建值 | PostgreSQL 连接串（`Database__Provider=npgsql` 时生效） |
| `Database__Provider` | | `sqlite` | 数据库提供方：`sqlite`（SQLite，零配置默认）/ `npgsql`（PostgreSQL，生产建议，docs/11）；compose `web-pg` 栈显式设为 `npgsql` |
| `ConnectionStrings__Sqlite` | sqlite 时可选 | 未配置时按 `/data` 存在性解析：容器内 `/data/atomupdate.db` / 本地开发应用根 `atomupdate.db` | SQLite 库文件路径；显式配置优先（docs/11 §3.1） |
| `Storage__Root` | | `uploads`（应用根相对）；compose 内 `/data/uploads` | 更新包资产落盘目录，`/uploads` 静态分发指向此处（docs/05 §9） |
| `IdGen__GeneratorId` | | 代码/appsettings 默认 `0`；compose 内设 `1` | 雪花 ID 发生器编号（多实例部署须互异） |
| `Auth__Jwt__AutoKeyFile` | | SQLite 库文件同目录 `jwt-signing-key.txt` | 自动生成 JWT 密钥的落盘路径覆盖（仅单实例形态适用） |
| `AdminApi__BaseUrl` | | `http://localhost:8080/` | Web 前端访问 Api 的基地址 |
| `ASPNETCORE_ENVIRONMENT` | | `Production`（compose 内设） | 运行环境 |

> 运营参数（日志保留天数、检测记录每应用上限等）不在环境变量中配置——由平台管理员在「管理后台 → 系统设置」调整，存 `Settings` 表（DB 有值优先，代码默认值兜底），保存后即时生效无需重启（docs/03）。

## 3. 数据与备份

- 数据卷：`pgdata`（PostgreSQL 数据）与 `uploads`（挂载 web 容器 `/data/uploads`，即 `Storage:Root`，更新包资产落盘目录）。**备份 = 备份这两个卷**（pg 卷可用 `docker run --rm -v atomupdate_pgdata:/data -v ${PWD}:/backup busybox tar czf /backup/pgdata.tgz -C /data .` 或 `pg_dump`；uploads 卷同理整目录打包）。
- 包资产经 `/uploads` 静态分发对外提供下载：Packager 经服务端上传端点（JWT Bearer）写入，Api 同步计算 SHA-256 并存元数据。
- SQLite 形态：数据 = `sqlite-data` 卷（库文件 + 自动生成的 JWT 密钥文件）+ `uploads` 卷。备份为文件级复制：在线复制前先执行 `PRAGMA wal_checkpoint(TRUNCATE)`（或直接停容器再复制），不能使用 `pg_dump`（docs/11 §3.5）。
- **JWT 密钥文件（`/data/jwt-signing-key.txt`）与库文件同卷**：丢失后自动重新生成，已签发 token 全部失效（重新登录即可），不影响数据。

## 4. 已知限制（MVP）

- **DataProtection 用临时密钥（设计决策）**：`Program.cs` 显式 `UseEphemeralDataProtectionProvider()` 并停用默认密钥环，密钥纯内存、从不落盘——容器重建后重新生成即可，无需挂卷。DataProtection 仅服务 antiforgery 令牌（重建后重新获取页面即可）；已签发 JWT 用独立的 `JWT_SIGNING_KEY` 签名，不受影响。
- 纯 HTTP 部署时 `HttpsRedirection` 仅警告透传；生产请前置 TLS 终止（反代/网关）。

## 5. 拓扑与端口

| 服务 | 容器 | 端口 |
|---|---|---|
| web（默认形态：Api+后台一体，SQLite） | atomupdate-web-1 | 8081（宿主） |
| postgres（`--profile postgres`） | atomupdate-postgres-1 | 5432（默认不暴露宿主机，按需取消注释） |
| web-pg（`--profile postgres`，与默认 web 二选一） | atomupdate-web-pg-1 | 8081（宿主） |

包分发由 web 容器内置的 `/uploads` 静态分发承接（指向 `Storage:Root`，先于鉴权公开可读），无需额外静态服务；如需 CDN 加速或对象存储，在 `/uploads` 之外另行前置（docs/05 §9）。

## 6. 构建与发布流水线

| 触发 | 工作流 | 动作 |
|---|---|---|
| push main / PR | `.github/workflows/ci.yml` | restore→build→test；6 RID AOT 更新器；打包 NuGet（内嵌更新器）为 artifact；Web Docker 镜像冒烟构建（不推送） |
| push tag `v*` | `.github/workflows/publish-nuget.yml` | 校验 tag 与 `Directory.Build.props` 版本一致 → 构建测试 + 6 RID 更新器 → pack `AtomUpdate`/`Core`/`Abstractions` → 推送 nuget.org（需仓库 Secret `NUGET_API_KEY`）→ 创建 GitHub Release（附 nupkg）→ 追加 `docs/RELEASES.md` 发布记录并回提 main |
| push main / release | `.pipewright.yml` | 构建 Web 镜像并推送私有 registry `docker.atomlust.com`，SSH 部署到 dev/prod 环境 |

> NuGet 包首次发布前须在 nuget.org 手工注册 `AtomUpdate`、`AtomUpdate.Core`、`AtomUpdate.Abstractions` 三个包 ID（个人账号 API Key 限制；组织名下可自动创建）。手动发布脚本见 `tools/release-*.ps1`。
